# 전투 프로토타입 1단계 구현 계획 — 링, 당겨 쏘기, 조준 가이드, 로프 반동

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 세로 화면 3칸 배치 위에 링과 에이프런을 그리고, 화면을 끌어 내 유닛을 쏘면 로프에 튕기고 상대 유닛을 밀어내는 것까지 에디터에서 플레이할 수 있게 한다.

**Architecture:** 규칙과 물리는 유니티를 참조하지 않는 순수 C# 어셈블리(`RingsideHearts.Battle.Core`)에 두고, 샷 한 번을 끝까지 계산해 "프레임별 위치 + 일어난 일 목록"을 돌려준다. 유니티 쪽(`RingsideHearts.Battle.View`)은 uGUI 하나로 화면 3칸, 링, 유닛, 조준선을 그리고 그 결과를 재생한다. Core는 `dotnet test`로 에디터 밖에서 바로 테스트하고, 같은 테스트 파일을 유니티 Test Runner도 쓴다.

**Tech Stack:** Unity 6000.0.83f1, URP 17.0.4, Input System 1.19(새 입력만), uGUI 2.0(레거시 `Text` + OS 글꼴), NUnit 3.14, .NET SDK 7.0(테스트 하네스), Unity CLI + Pipeline 패키지(에디터 조종)

**Spec:** [Docs/전투-프로토타입-설계-v0.1.md](../전투-프로토타입-설계-v0.1.md) (6장, 10.2장, 11장, 13장, 14장 1단계)

## Global Constraints

- Core 코드는 C# 9까지만 (유니티 컴파일러). record, init, 파일 범위 namespace 금지. asmdef `noEngineReferences: true`
- Core에 숫자를 직접 쓰지 않음. 모든 조정 값은 `Assets/Resources/Data/tuning.csv`의 키로 읽음
- 결정적 계산: 고정 간격 `sim.dt`, `System.Random`은 시드 지정으로만, 시간 함수 금지
- 링 좌표: 로프 안쪽 정사각형의 왼쪽 아래가 (0,0), 오른쪽 위가 (`ring.size`, `ring.size`), y는 위쪽
- 화면 기준 해상도 1080×1920. 세로 3칸 = 상단 250 / 링 1080(정사각형) / 하단 나머지. 에이프런 띠 = 링 칸 폭의 12%씩, 로프 안쪽 = 76%
- 링과 에이프런 위에는 어떤 UI도 겹치지 않음 (설계 10.2 [확정])
- MonoBehaviour는 클래스 하나당 파일 하나, 파일 이름 = 클래스 이름
- UI 글자는 한국어. 글꼴은 `Font.CreateDynamicFontFromOSFont`에 후보 목록 `Malgun Gothic`, `Noto Sans CJK KR`, `Noto Sans KR`, `NanumGothic`
- 에디터가 열려 있으면 `.unity` 파일을 직접 고치지 않음. 장면 생성과 설정 변경은 `unity command`로

충돌 규칙 (설계 6장): 두 Solid 몸의 중심 거리 < 반지름 합이고 서로 다가가는 중일 때만. 법선 n = (B − A)/거리, 거리가 0이면 n = (0,1). 부딪친 쪽 = 법선 방향 속도 성분이 큰 쪽. 맞은 쪽 속도 += n × (부딪친 쪽 속력 × `hit.knockback`). 부딪친 쪽 속도 = `Reflect(v, n) × hit.attackerRestitution`. 겹친 만큼 부딪친 쪽을 뒤로 밀어 떼어 놓음
