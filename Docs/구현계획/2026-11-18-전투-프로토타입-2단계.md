# 전투 프로토타입 2단계 구현 계획 — 스태미나, 다운, 플랜, 연타 3종, 상대 행동, 승패

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 레오(내 팀, 사람) 대 볼트(상대 팀, AI) 1:1로, 쏘고 맞고 다운시키고 플랜을 골라 연타 힘겨루기로 끝내거나 턴 제한으로 지는 한 판을 에디터에서 끝까지 플레이할 수 있게 한다.

**Architecture:** 판의 규칙은 전부 Core(순수 C#)에 둔다. `ShotResolver`가 1단계의 `RingSim` 결과(프레임 + 사건)를 읽어 피해, 다운, 피날레 발동을 계산하고(상태를 바꾸지 않음), `Match`가 그 결과를 적용하며 턴 순서를 진행한다. 연타 판정(`Mash`)과 상대 AI(`EnemyAi`)도 Core에 있어서 AI 대 AI 한 판을 테스트로 끝까지 돌린다. 양 팀은 같은 `Fighter`/`TeamState` 코드를 쓰고 `TeamSetup`(teams.csv 한 줄)만 다르다. View는 `Match`의 상태를 읽어 그리고, 입력을 `Match`/`Mash`에 넘긴다.

**Tech Stack:** 1단계와 같음 (Unity 6000.0.83f1, uGUI + 레거시 Text, Input System, NUnit 3.14 + `dotnet test Tools/CoreTests`, Unity CLI)

**Spec:** [Docs/전투-프로토타입-설계-v0.1.md](../전투-프로토타입-설계-v0.1.md) (4.1, 5장, 8장, 9.1, 10.2~10.4, 14장 2단계), [Docs/전투-시스템-기획-v0.2.md](../전투-시스템-기획-v0.2.md) (5.2, 6, 7, 8, 12장)

## Global Constraints

- Core 코드는 C# 9까지 (record, init, 파일 범위 namespace 금지). asmdef `noEngineReferences: true`
- 조정 숫자는 Core에 직접 쓰지 않음. 한 벌짜리 값은 `GameVariables` 에셋 → `Tuning` 키, 캐릭터와 팀 값은 `Assets/Resources/Data/characters.csv`, `teams.csv` (UTF-8 BOM)
- 결정적 계산: 난수는 Core의 `Rng`(시드 지정)만, 시간 함수 금지. 같은 시드 + 같은 입력 = 같은 결과
- 양 팀 같은 구조 [확정 4.1]: 팀에 따라 갈리는 코드 분기는 `TeamSetup` 값(조작, 행동 간격, 배율, AI 정확도)으로만. "team 0이면 플레이어" 같은 분기 금지. 예외는 턴 제한 패배 쪽(아래 P27)뿐
- 링과 에이프런 위에 UI를 띄우지 않음 [확정 10.2]. 예외: 피날레 컷인(설계 10.3), 결과 화면
- MonoBehaviour는 클래스 하나당 파일 하나. UI 글자는 한국어
- 에디터에서 확인할 때: 파일을 바꾼 뒤 `AssetDatabase.Refresh()` → 컴파일 끝난 것을 확인한 다음 플레이 모드에 들어감
- 3단계 이후 몫은 만들지 않음: 태그, 대기 선수, 열기 변화, 어필, 속성 배율, 타입 동작, 필살기, 세컨드, 매치 선택 화면

### Task 2: 선수 상태와 샷 판정 (피해, 반동, 라리아트, 다운, 피날레 발동)

**Files:**
- Create: `Assets/Game/Battle/Core/Match/Fighter.cs`, `FinalePlan.cs`, `ShotResolver.cs`
- Test: `Assets/Tests/EditMode/Core/ShotResolverTests.cs`

**Interfaces:**
- Consumes: Task 1 `CharacterData`, `TeamSetup`, Tuning 키. 1단계 `RingSim.Simulate(bodies, shooter, velocity)`, `SimEvent`(RopeBounce, RopeLeave, BodyHit)
- Produces:
  - `enum FinalePlan { Pinfall, Submission, Ringout }`
  - `sealed class Fighter { CharacterData Data; int Team; float MaxStamina; float Stamina; float Power; float Guts; bool IsDown; Vec2 Position; float StaminaRatio; Fighter(CharacterData d, TeamSetup s, int team, Vec2 position); }` — MaxStamina = Stamina × StaminaMul, Power × PowerMul
  - `sealed class HitRecord { float Time; Vec2 Position; float Damage; int RopeBounces; bool Lariat; bool CausedDown; }`
  - `sealed class FinaleTrigger { int AttackerTeam; int DefenderTeam; FinalePlan Plan; bool NearRope; float Time; }`
  - `sealed class ShotOutcome { ShotResult Shot; List<HitRecord> Hits; FinaleTrigger Finale; float TotalDamage; bool CausedDown; int LariatCount; float TargetStaminaAfter; }`
  - `static class ShotResolver { static ShotOutcome Resolve(RingSim sim, Tuning t, Fighter shooter, Fighter target, FinalePlan plan, Vec2 velocity); static bool IsNearRope(Vec2 p, Tuning t); }` — 몸 인덱스 0 = shooter, 1 = target. 상태를 바꾸지 않음

판정 규칙 (사건을 시간 순으로 한 번 훑음):
- shooter의 RopeBounce → 반동 수 +1. target의 RopeBounce → (이번 샷에서 맞은 적이 있으면) 라리아트 준비. 링아웃 접촉이 기록돼 있고 `NormalSpeed ≥ ringout.minSpeed`면 링아웃 피날레 발동
- 0과 1 사이 BodyHit (누가 striker든) = shooter가 target을 친 것
  - 샷 시작 때 target이 다운 중: 피해 없음(P26). 핀폴/서브미션은 첫 접촉에 발동(`NearRope` = 접촉 순간 target 위치로 판정), 링아웃은 접촉만 기록
  - 이번 샷에서 target을 다운시켰으면: 이후 접촉은 아무것도 안 함 (P9)
  - 그 밖: 피해 = Power × `damage.scale` × (1 + `rope.bonusPerBounce` × min(반동 수, `rope.bonusMax`)) × (라리아트면 `hit.lariat`). 반동 수 0으로, 라리아트 준비 해제. 남은 스태미나가 0 이하면 0으로 두고 `CausedDown`
