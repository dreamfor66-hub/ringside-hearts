# 제작 준비 체크리스트 v0.1

작성일: 2026-11-16
목적: Claude가 실제 제작을 맡기 전에, 무엇이 정해졌고 무엇이 비어 있는지 정리합니다.

## 0. 읽는 법

- **[사용자]**: 사용자가 정하거나 자료를 줘야 하는 것. 제가 대신 정할 수 없거나, 정하면 안 되는 것
- **[Claude]**: 제가 기획서로 채울 수 있는 것. 지금까지처럼 임의 결정 번호를 붙여 씀
- 각 항목의 **추천**은 사용자가 따로 말하지 않으면 제가 그대로 진행할 기본값입니다

## 3. 사용자에게 받을 자료

### 3.1 UI 비주얼 방향 [사용자]
UI는 "어떤 느낌인지"를 말로 맞추기 어렵습니다. 아래 중 하나로 주시면 됩니다.
- 좋아하는 게임 UI 스크린샷 3~5장 (로비, 전투, 가챠 화면이면 가장 좋음)
- 또는 아래 방향 중 고르기 (제가 각각 시안 배치도를 만들어 드릴 수 있음)

| 방향 | 느낌 |
|---|---|
| 레슬링 흥행 포스터 | 굵은 글씨, 대각선 구도, 강한 원색. 70~90년대 프로레슬링 포스터 |
| 네온 아레나 | 어두운 바탕에 네온 조명, 스포트라이트. 히트 이펙트가 돋보임 |
| 만화 잡지 | 칸 나눔, 효과선, 의성어 글자. 컷인과 잘 맞음 |

### 3.2 전투 화면의 작은 유닛 [완료]
**[확정] 보드 위에 서 있는 SD. 원형 토큰은 프로토타입에서만.** 일러스트 SD 3포즈로 정한 내용은 [아트 제작 가이드](아트-제작-가이드-v0.1.md) 3장. 아래는 처음 물어볼 때의 표입니다.

전투 중 링 위에 보이는 작은 캐릭터의 형태가 아직 없습니다. 제작 공수에 바로 영향을 줍니다.

| 방식 | 제작 | 느낌 |
|---|---|---|
| 원형 토큰 + 얼굴 아이콘 | 가장 쉬움. 전신 일러스트에서 얼굴만 잘라 씀 | 몬스터 스트라이크 |
| SD(작은 2등신) 캐릭터 1장 | 캐릭터당 1장 추가 | 귀여움, 캐릭터가 보임 |
| SD + 간단한 움직임 | 캐릭터당 여러 장 또는 뼈대 애니메이션 | 가장 생동감 있음, 비용 큼 |

프로토타입은 원형 토큰으로 시작하고, 방식은 그다음에 정해도 됩니다.

### 3.3 캐릭터 풀 니즈 [완료]
사용자 답: 여우, 드래곤·파충류, 조류, 상어, 중년, 할아버지, 비만. 아주 큰 거구는 몬스터가 맡음. 출시 24명 안과 추가 9명은 [캐릭터-로스터-확장-v0.1.md](캐릭터-로스터-확장-v0.1.md). 아래는 처음 물어볼 때의 표입니다.

출시 15명을 보면, 이 팬덤에서 수요가 큰데 아직 없는 종과 유형이 있습니다.

| 빠진 것 | 메모 |
|---|---|
| **여우** | 퍼리 팬덤에서 가장 인기 있는 종 중 하나 |
| **드래곤, 파충류** | 비늘 계열 수요. 현재 악어 1명뿐 |
| 조류 | 레전드 보스(독수리, 박쥐)에만 있음 |

- 선택이 오면 출시 로스터 일부를 바꾸거나, 첫 3개월 신규 캐릭터로 배치하겠습니다

## 5. 확장하기 쉬운 구조 — 제작 원칙

요청하신 "캐릭터, 던전, 몬스터를 쉽게 추가할 수 있는 구조"를 위한 원칙입니다. 프로토타입부터 이 구조로 만듭니다.

### 5.1 데이터 주도
- **캐릭터, 스킬, 스테이지, 적, 보스, 매치 규칙, 장비, 이벤트, 가챠 배너는 모두 데이터**로 정의함
- 데이터 원본은 스프레드시트. 가져오기 도구가 게임용 데이터로 변환함
- 목표: **캐릭터 한 명 추가 = 스프레드시트 몇 줄 + 정해진 폴더에 그림 넣기. 코드 수정 없음**

### 5.2 효과 블록으로 스킬과 기믹 만들기
- 스킬, 세컨드 스킬, 장비 효과, 보스 기믹, 지역 규칙을 모두 **"언제 + 누구에게 + 무엇을"** 블록 조합으로 표현함
  - 예: 아이스버그 세컨드 스킬 = [항상] + [짝 선수] + [다운 회복 속도 +15%]
  - 예: 3장 지역 규칙 = [항상] + [모든 선수] + [로프 반동 보너스 ×1.5]
  - 예: 철문 보스 기믹 = [항상] + [보스] + [핀폴 무효]
- 새로운 종류의 효과가 필요할 때만 코드로 블록을 하나 추가함. 한번 만든 블록은 다른 캐릭터와 보스에도 재사용됨
- 블록 조합으로 안 되는 고유 기믹은 전용 코드를 연결할 수 있는 예외 통로를 둠

### 5.3 추가 절차
| 추가하는 것 | 필요한 것 |
|---|---|
| 캐릭터 | 데이터 1줄, 스킬 블록, 그림 세트 |
| 모브 레슬러 | 데이터 1줄, 작은 유닛 그림 |
| 보스 | 데이터 1줄, 기믹 블록, 그림 |
| 스테이지·던전 | 스테이지 데이터 (지역 규칙, 매치 규칙, 상대 편성, 보상, 장면 번호) |
| 이벤트 | 이벤트 데이터, 스테이지 묶음, 상점 목록, 스크립트 |
| 스토리 | 스크립트 파일 |

### 5.4 앱 업데이트 없이 새 콘텐츠 배포
- 매달 나오는 캐릭터와 이벤트를 앱 업데이트(스토어 심사) 없이 내려받게 함 (Unity Addressables + 원격 저장소)
- 가챠 배너, 이벤트 일정, 일부 수치는 원격 설정으로 바꿀 수 있게 함

### 5.5 자동 검증과 개발 도구
- 데이터를 넣을 때 그림 누락, 잘못된 스킬 참조, 숫자 범위 오류를 자동으로 잡음
- 개발용 메뉴: 재화 지급, 스테이지 바로 가기, 전투 배속, 캐릭터 전부 해금
- 전투 결과를 다시 재현할 수 있게 해서 버그를 찾기 쉽게 함

## 7. 이미지 생성 연결 (참고)

**2026-11-17 갱신**: 사용자 도구는 NovelAI V4.5 Full Furry로 확정. 아래 표의 "이미지 생성 API" 방식에 해당합니다. NovelAI 영구 API 토큰을 환경 변수에 넣으면 Claude가 배치 생성과 1차 선별을 맡을 수 있습니다. 자세한 흐름은 [아트 제작 가이드](아트-제작-가이드-v0.1.md) 2.2.

Claude가 맥락을 가진 채 직접 그림을 만들려면, Claude가 이미지 생성 도구를 **직접 호출**할 수 있어야 합니다. 지금 이 환경에는 연결된 이미지 생성 도구가 없고, MCP 레지스트리에도 맞는 공식 커넥터는 보이지 않았습니다.

| 방법 | 어떻게 | 장점 | 주의 |
|---|---|---|---|
| **로컬 ComfyUI** (권장) | 사용자 PC에서 ComfyUI를 켜 두면, Claude가 그 API로 워크플로를 실행하고 결과 파일을 받아 옴 | 사용자가 쓰던 모델과 로라를 그대로 씀. 비용 없음. 스타일 유지가 쉬움. 포즈 지정(컨트롤넷)으로 핀폴 포즈 같은 규격 그림도 가능 | 처음 한 번 워크플로 설정이 필요함. GPU 필요 |
| 이미지 생성 API | 사용자가 API 키를 환경 변수로 넣어 두면, Claude가 스크립트로 호출 | 설치가 간단함 | 사용량 비용. 서비스별로 수인 캐릭터 품질과 콘텐츠 정책이 다름 |
| 커뮤니티 MCP 서버 | 이미지 API를 감싼 MCP 서버를 Claude Code에 추가 | 대화 안에서 바로 호출 | 공식이 아니라 직접 검증이 필요함 |
| 웹 서비스 (API 없음) | — | — | Claude가 직접 연결할 수 없음. 지금처럼 프롬프트를 넘기는 방식만 가능 |

연결되면 이런 흐름이 됩니다.
1. 캐릭터 설정집에서 프롬프트를 만듦
2. 생성 → Claude가 결과를 직접 보고 고르거나 다시 뽑음
3. 배경 제거, 크기 조정, 규격에 맞춰 자르기
4. 게임 폴더의 정해진 위치에 넣고 데이터에 등록
